# Mock composition proposals

Created from owner authorization to complete reviewable mockups now. These are visual proposals for stakeholder review, not human-approved policy or production screens.

## Shared direction

Use the DESIGN.md token proposal supplied by the UX agent: cream canvas #F7F5EC, forest #244B3C, white surfaces, #23362D ink, #56645B secondary text, system sans-serif with Georgia display headings, 20px card corners, 12px controls, 44px targets, and clear blue focus. Offline HTML with inline CSS and ordinary links/native controls only. No app framework, external requests, real authentication, backend, sending, or transactions.

All visible sample businesses, offerings, prices, ratings, addresses, states and counts are fictional demonstrations. Every page carries a clear preview notice. The generated meal image is illustrative, not evidence of a listed business. Brand name/copy and precise fields are proposed.

## Surfaces

- Directory: airy hero with food photo; visible location and text search; sidebar filters on desktop; native filter disclosure on mobile; three horizontal ProviderCard rows; names, aggregate/count, address, service tags, matching menu text and contact gate.
- Provider: food gallery, name/address/reviews, service coverage, searchable structured menu/package cards and supplementary menu preview; explicit contact gate plus a separately labelled signed-in state; ownership claim and Reviews links.
- Sign-in: narrow calm AuthForm, Google/email choices, explicit return-to-provider context; no real OAuth or email dispatch.
- Onboarding: Company/service area/menu-photo form, live-style preview shown statically, and explicit submitted/pending state in a second section.
- Admin listings: AdminNav, publishing queue, proposed listing fields, source/ownership status, and approve/request-changes/reject dispositions illustrated without performing actions.
- Admin discovery: CandidateEvidence source details, directory duplicate match warning, review/edit fields, separate publish and invitation sections, ineligible channel reason and remaining queued state.
- Admin moderation: reported Review context/original text, reason and proposed moderation dispositions; simple feedback panel. Separate threaded comments are not introduced.
- Claim: verification evidence form and submitted/pending result; no editing access granted on submission.
- Review: rating and optional text, one editable contribution, acknowledgement and existing-review edit state.
- States: manual location fallback, no results, save retry, and missing supplementary menu; location use is represented without accessing device permissions.
- Settings: daily time/timezone fields, last-run outcome and source/channel eligibility. Actual integrations remain feasibility-dependent.
- Review gallery: route map with links, desktop and phone previews, reading order and artifact links. This is review navigation outside the proposed customer product flow.

Responsive proposal: 1200px maximum content, 32px desktop/16px mobile gutters; directory sidebar 240px; mobile horizontal cards keep 88px photo alongside text with actions on the next row. Admin navigation wraps to a horizontal list; queues become stacked entries rather than clipped tables.
